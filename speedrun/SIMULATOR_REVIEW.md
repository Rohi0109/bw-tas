# Simulator implementation review

Reviewed the campaign implementation introduced in `fe1acde`, then reran tests
and added checkpoint-validation fixes. Results below were executed locally, not
inferred from prior conversation or generated by the local model.

## Findings

- **High: native campaign fidelity remains unimplemented.** Enemy-specific AI
  overrides, native effects/queues, progression/save logic and the native shared
  RNG schedule are not reproduced. The implementation is a declarative scenario
  engine and correctly marks reports `native_parity: false`. Passing its tests
  does not satisfy the original full-game simulator acceptance gate.
- **Medium, fixed: contradictory completion checkpoints were accepted.** A
  checkpoint could set `encounter=2` and `status=campaign-complete` while the
  enemy retained full HP and XP stayed zero. Validation now checks terminal HP,
  encounter counters, reward XP and maximum player HP against the definition.
  False `no-playable-word` states are also rejected.
- **Medium, fixed: RNG ledger/cursor inconsistencies were accepted.** Import
  now checks the cursor against the total draw count, including twist boundaries.
  This is a consistency check, not authentication of all 624 state words: an
  intentionally edited but self-consistent snapshot is still a scenario input.
- **Coverage limitation:** current effect tests are scenario assertions, not
  independent native traces. Campaign tests cover only small synthetic encounters.
  Shield expiry follows the documented owner-turn policy; it is not confirmed
  native behavior. No native game, controller or screenshot was used in this review.
